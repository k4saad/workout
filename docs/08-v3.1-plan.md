# v3.1 plan — from the first week on the phone

Saad's report after installing 0.12.0+12, and what the code says caused it.

| Report | Cause, found in the code |
|---|---|
| GPS always "Finding GPS", always "weak" | Start stays disabled until ONE fix is ±25 m or better (`RunTracker.readyAccuracyM`). With Android's **Approximate** location granted, accuracy is ±1–2 km forever, so it never unlocks, and nothing says why. With precise location, a first fix of ±30–60 m is normal, and ±25 m on the first try is luck. |
| "Phone already has a running app" | The position stream carries geolocator's foreground-service notification **from the moment the screen starts looking for GPS**, not from Start. And a Start with no fix leaves a run row open, which Today then reports as "Run still open". |
| Map looks like satellite, too detailed | Full-colour OSM street tiles passed through `darkModeTileBuilder`, which inverts them: every building, shop icon and landuse colour, reversed. Opened at zoom 16.5, where every building is drawn. |
| Runs should look like Strava | One flat 5 px line, no position dot, no animation. |
| Fuel: plan the week ahead | Only today exists. There is a grocery sheet but no week view, no prep plan. |
| Chicken AND salmon in one day | Each slot defaults to `options.first`, so every day is chicken lunch + salmon dinner. There is no idea of cost. |
| Swipe between tabs | Tabs change only from the bottom bar (`FadeBranchContainer`). |

The rules still stand: no new dependency, no new permission, no new network
host without asking. One item below needs his word and is NOT done: a
cleaner vector-style basemap (CARTO "dark matter") would be a second tile
host. Everything here stays on `tile.openstreetmap.org`.

Every phase ends on the gate: analyze clean, tests green, V1–V21, screens
looked at, `dart format`, one commit.

---

## Phase A — GPS that locks

1. **Precise location.** `LocationSource.isPrecise()` (geolocator's
   `getLocationAccuracy`). Approximate → a new `TrackerStatus.approximate`
   with a plain banner: "Precise location is off. A run needs it." and a
   button to the app's settings. Checked again on resume.
2. **Start whenever permission is there.** The button is never greyed out
   waiting for a perfect fix. States shown: *Waiting for GPS* (no usable fix
   yet), *GPS fair ±N m*, *GPS good ±N m*. Starting before a usable fix
   starts the clock; the trail begins at the first usable fix.
3. **Thresholds that fit a real phone.** Good ≤ 12 m, fair ≤ 30 m. The
   recording filter accepts up to 40 m: distance is already counted in
   steps of ≥ max(4 m, ½ accuracy), so a vaguer fix adds trail, not false
   distance. Test-first in `fix_filter`/`run_track`/tracker tests.
4. **A quick first position.** Last known position shown at once (not
   counted), so the map is not blank while the GPS warms up.
5. **The notification only while recording.** Looking for GPS uses a plain
   foreground stream. Start switches to the foreground-service stream
   ("Recording your run"); finish, discard or leaving stops it.
6. **No phantom open runs.** Leaving the live screen with nothing recorded
   discards the run. `RunRepository.tidyEmptyRuns()` removes open runs with
   no points (on open, like empty shoots). Today's "Run still open" only
   appears for a run with a trail.

## Phase B — Runs like Strava

1. **A quiet map.** Same OSM tiles, drawn through a greyscale, dimmed,
   low-contrast filter (not an inversion): roads read as soft grey lines on
   near-black, buildings and icons fade away. Live view opens at zoom 15.
2. **The trail.** 6 px, crimson, rounded, with a dark border and a soft glow
   underneath — it is the brightest thing on the screen.
3. **Live.** A pulsing position dot with an accuracy halo; map follows; the
   layout of a run app: map on top, a stats panel with huge time, distance
   and pace; big round Pause / Resume / hold-to-Finish.
4. **After the run.** The summary opens with the route drawing itself
   (~1.6 s), then the numbers count up. A toggle colours the route by pace
   (quicker = brighter). A **Replay** button runs a dot along the route with
   the distance and time ticking.
5. **Run page.** Map hero across the top, a stat grid (distance, moving
   time, pace, climb), splits as bars with the quickest marked, pace chart,
   effort.
6. **Runs list.** Activity cards: "Evening run · Easy run", date, three
   numbers, a large trail thumbnail in crimson.
7. Every animation respects reduced motion.

## Phase C — Fuel on a student budget, planned by the week

1. **Prices.** `tools/gen_fuel.py` gains an estimated € per kg for every
   food — German discounter shelf prices, marked as estimates in the app
   ("check your receipt"). Every meal and day carries its cost.
2. **A rotation, not a first-in-list default.** The generator builds a
   7-day rotation per training/rest pattern:
   - **one main protein per day** (lunch and dinner share it, cooked once):
     chicken thighs, eggs, lentils, tuna, chickpeas, mince — rotated;
   - the cheap backbone every day: oats, milk, quark, rice/pasta/bread,
     bananas, peanut butter;
   - **salmon is out of the defaults** (still a swap, marked as the
     expensive one);
   - a daily cost ceiling, **about €6** — roughly €40 a week.
   Gate **V21**: no default day has two meat/fish mains; every default day
   hits its kcal (±3 %) and the protein floor; the week's cost is under the
   ceiling; still halal (V-halal unchanged).
3. **Batch cooking.** Meals flagged `batch` (rice, lentils, chicken thighs,
   bulgur) are grouped into a prep plan: "Sunday evening: cook 600 g rice,
   900 g chicken thighs — covers Mon–Wed lunches and dinners"; a second
   session mid-week.
4. **Fuel → Plan.** Fuel gets two sections, *Today* and *Plan*. Plan shows
   *This week / Next week*:
   - seven day cards with their meals (tap to swap, as today) and the day's
     cost;
   - the week's **prep plan** (what to cook, when, how much);
   - the week's **shopping list** by aisle, rounded to packets, with an
     estimated total and tick-boxes remembered per week.
5. Today's screen keeps working exactly as now, reading the same rotation.

## Phase D — Swipe between tabs

1. The five tabs sit in a swipeable pager: swipe Fuel → Week and back, the
   bottom bar follows, and each tab keeps its place (branches pre-built and
   kept alive). A haptic tick on each change; reduced motion jumps.
2. **Conflicts, decided:**
   - the Week tab's body no longer swipes between weeks (that would steal
     the tab swipe); weeks change with the arrows, a swipe on the week
     header, and "This week";
   - pages opened from a tab (calendar, photos, a run's map, the compare
     slider) keep their own horizontal gestures; the tab swipe works on the
     five tab screens themselves.
3. Back still walks up each tab's own stack; a swipe never pops a page.
